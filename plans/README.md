## Findings considered and rejected

Audit findings vetted and dropped (do not re-audit these):

- **BUG-02/03/05/06 "check-then-act races" (Map access in learning-pipeline,
  orchestrator error tracking, stageResults, WS disconnect cleanup)**: rejected —
  the cited code paths are synchronous JavaScript with no `await` between check
  and act; single-threaded event loop makes the claimed interleavings impossible.
- **BUG-01 "nested transaction can corrupt instincts migration"**: rejected —
  `learning-storage.ts` wraps the whole migration in BEGIN/COMMIT with a proper
  `ROLLBACK` in the catch (line ~550); the helper's statements execute inside
  that transaction atomically.
- **BUG-04 "resume checkpoint lost on persist failure"**: rejected — the catch
  path explicitly re-persists the checkpoint with a timestamp bump
  (`orchestrator.ts` ~2162); the claimed scenario is the one the code handles.
- **SEC-03 "URL-encoded null-byte path traversal in vault routes"**: not
  exploitable — `resolveSafeVaultReadPath` (`src/vault/path-policy.ts:214`) has
  layered absolute/normalize/symlink-ancestor/realpath defense, and Node `fs`
  rejects NUL bytes in paths. A `%00` pattern check is included in plan 004 as
  consistency hardening only.
- **SEC-05 "unauthenticated vault search"**: overstated — all `/api/` routes
  require bearer auth when a dashboard token is configured, and mutating routes
  require trusted same-origin otherwise (`server.ts:606-614`). The residual gap
  (no per-IP rate limit) is plan 004 step 2.
- **SEC-13 "CSRF bypass when Origin omitted"**: rejected —
  `requireTrustedDashboardMutation` returns 403 when neither Origin nor Referer
  is present; browsers send Origin on cross-origin POSTs. Residual improvement
  (startup warning when no token) is plan 004 step 3.
- **SEC-08 "ring buffer secrets exposed via GET /api/logs"**: partially wrong —
  `server-system-routes.ts:332-344` already sanitizes at read time. The real gap
  is the two other ring-buffer consumers feeding raw entries into LLM prompts
  (clarification + intervention pipelines); that is what plan 004 step 1 fixes.
- **"react-router RCE makes the portal remotely exploitable"**: overstated — the
  portal is a client-side Vite SPA using only BrowserRouter/Routes/NavLink-class
  APIs; the RCE and most XSS advisories target framework mode/SSR/RSC. Plan 001
  still bumps (the fix is free), but this is not an incident.
- **PERF-03 "activeGoalTrees grows unbounded"**: rejected —
  `orchestrator-session-manager.ts:269,686` evicts goal trees with session
  cleanup; growth is bounded by active sessions.
- **"30MB src/channels/web/static bloats the repo"**: rejected — only a single
  placeholder `index.html` is committed; the 30MB is local build output.
- **DIR-05 "incoming audio transcription is not wired" (would-be plan 014)**:
  disproven — `transcribeIncomingAudioMessage` runs at the head of the incoming
  pipeline in both modes (`bootstrap-wiring.ts:52-60`, `bootstrap.ts:1268-1276`),
  the portal records and ships audio attachments, STT modes and failure fallback
  exist, with tests. Nothing to do.
- **DIR-01 "no backend handler for /api/settings/voice"**: wrong root cause —
  the handler exists (`server-settings-routes.ts:115-162`); the real bug is a
  field-name contract mismatch (portal sends `inputEnabled`/`outputEnabled`/
  `browserSttEnabled`, backend reads `enabled`/`language`/`speed`) so POSTs
  silently persist nothing. Re-scoped as plan 015.
- **DEP-11 "picomatch is an unused direct dependency"**: wrong — direct import at
  `src/daemon/triggers/file-watch-trigger.ts:18`. Plan 012 keeps it.
- **"Add *.log / *.tgz / tsbuildinfo to .gitignore"**: already covered
  (.gitignore lines 5/6/19); plan 010 only verifies via `git check-ignore`.
- **DEBT-10 "workload dimension weights duplicated"**: partially outdated —
  `provider-knowledge.ts` already imports `WORKLOAD_DIMENSION_WEIGHTS`; the
  remaining duplication is the feature-flag formula table + 40/60 blend, which is
  plan 011's actual target. (Also: `provider-behavioral-profiles.test.ts` exists,
  369 lines — the "no tests" note elsewhere is stale.)
- **"ObsidianVault.writeFile is temp+rename atomic"**: wrong — it is an
  Obsidian-REST write with plain FS fallback; the temp+rename atomicity lives in
  canvas regeneration. Plan 006 tests what actually exists.
- **Zod v3→v4 migration**: deferred by decision — breaking-change migration with
  real cost on validation-critical paths; revisit at the next major version.
- **discord.js v14→v15 migration**: not now — plan 012 takes the v14 patch only;
  v15 is a separate future migration.
- **"Generate .env.example by grepping `process.env.X` in config.ts"**: the
  extraction command was wrong — config.ts reads env via an `env["VAR"]` map
  (282 distinct vars). Plan 002 inlines corrected commands.
